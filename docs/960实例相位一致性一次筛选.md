# 960 基线：实例约束的采样相位一致性

方案冻结日期：2026-10-11，版本 v1。

保留已完成的 YOLO11s / 960 / 100 epoch / batch 8 / seed 0 基线。
只训练一个新候选，不继续调整 SDCL 权重。候选从同一个原始
`yolo11s.pt` 初始化，避免把额外的 100 轮训练误认为方法收益。

## 研究假设和创新边界

960 的结果证明高分辨率训练有收益，但没有证明收益来自平移稳定性。
本方案检验的额外假设是：亚步长平移造成小目标特征和检出状态不稳定，
对密集小目标施加实例约束的对齐特征一致性，可能提高正常图像的 AP。

潜在研究切口是**小目标实例约束**，不是首次提出平移稳定性或一致性损失。
最接近的已核验文献：

- Manfredi and Wang, *Shift Equivariance in Object Detection*, ECCV 2020 workshop：
  检测器可以对一像素平移敏感，文中研究端到端检测的平移敏感性评估。
  https://arxiv.org/abs/2008.05787
- Saha and Gokhale, *Improving Shift Invariance in Convolutional Neural Networks
  with Translation Invariant Polyphase Sampling*, WACV 2025：
  摘要明确提出可学习 pooling，并报告分类、检测、分割的平移稳定性改进。
  本地方案没有替换 pooling，也没有实现 TIPS。
  https://openaccess.thecvf.com/content/WACV2025/html/Saha_Improving_Shift_Invariance_in_Convolutional_Neural_Networks_with_Translation_Invariant_WACV_2025_paper.html
- Lee et al., *Soft Equivariance Regularization for Invariant Self-Supervised
  Learning*, ICLR 2026：对中间空间特征施加软等变正则已存在。
  因而“中间特征 + 无额外推理头”也不是本方案独有的贡献。
  https://proceedings.iclr.cc/paper_files/paper/2026/hash/3be6511c8f56d0dca4b5ed59fdf9b2f4-Abstract-Conference.html
- Li and Li, *Transformation Invariant Few-Shot Object Detection*, CVPR 2021：
  摘要已提出不同变换图像的预测一致性正则。
  https://openaccess.thecvf.com/content/CVPR2021/html/Li_Transformation_Invariant_Few-Shot_Object_Detection_CVPR_2021_paper.html

截至冻结日期，只核验了上述论文的摘要/出版信息及检测平移敏感性描述。
部分 CVF 正文获取受限，未完成全文级或穷尽式新颖性审查。
本方案是可检验的候选贡献，不能据此宣称首创或足够发表。
如果筛选通过，之后仍需普通一致性与实例约束的消融、多 seed、第二数据集；
这一次实验只决定是否值得继续投入。

## 开始前的基线证据

固定抽取 548 张验证图中的 64 张，索引按图像名排序后等距选择。
将输入平移 `(1,3), (-3,1), (5,-2), (-2,-5)` 像素，不环绕，
露出的像素填充为 114/255。比较同一 GT 的原视图和对齐平移视图。
检出使用同类 IoU >= 0.5、confidence >= 0.25、NMS IoU 0.7、max_det 500。
过滤忽略区，排除距输入边界不足 32 像素以及平移后不满足边界约束的 GT。

初次探针 `output/analysis/phase_preflight_20261011/probe_v1.json`：

| 组 | 平均对齐特征余弦距离 | 检出状态翻转率 |
|---|---:|---:|
| tiny | 0.15930 | 11.667% |
| small | 0.08563 | 5.018% |
| medium | 0.03540 | 2.990% |

这些计数包含同一目标的多次位移，不能当作独立样本量或 AP。
特征距离采用排除邻近框与忽略区后的采样点；检出翻转采用全部边界安全 GT，
因此两项诊断的目标数不同。没有足够合格 large GT，不解释 large 的零值。
探针说明存在可观测的不稳定性，不证明它是漏检的主要原因。
最终评估会在同一份当前代码下重新运行两个检查点的探针。

## 唯一新增机制

`sdcl/training/phase.py` 实现以下训练过程：

1. 原视图计算正常检测损失，原有 TAL 分配、分类、回归和忽略区协议保持相同。
2. 以固定循环使用八个不超过 7 像素的亚 P3 步长平移，保持原来的整图尺寸。
   每两批增加一次共享模型、无梯度的平移前向。没有独立教师参数。
3. 从增强后的 GT 中选取参考长边 640 时等效边长 `sqrt(area) < 32` 的对象；
   不足 32 像素边界余量的对象排除。每张最多 256 个，用确定性等距索引截取，
   不额外消耗训练增强的随机数。
4. 每个目标框内部 1/4、1/2、3/4 位置形成 3×3 采样点。
   点落入其他 GT 框或忽略框时排除；没有有效点的对象不参与。
5. 在检测头输入的 P3 特征上，分别按原坐标和平移后坐标进行双线性采样。
   对各点计算通道方向的余弦距离，先在对象内平均，再在对象间平均。
   平移视图停止梯度。边界框不是精确分割掩码，排除点也不能隔离整个感受野；
   因此不宣称彻底消除邻居特征污染。
6. 第 0～5 个 epoch 的新增权重为 0；第 6～15 个 epoch 从 0.1 升至 1。
   每两批计算一次的损失乘以 2，以补偿计算频率。
   新增 `phase_loss` 单独记录，验证时该项为 0。

辅助前向使用训练 batch 统计，但不重复更新 BatchNorm running buffers。
采样用显式双线性 `index_select`，验证了严格 deterministic CUDA backward，
避免直接使用不支持确定性 CUDA 反向的 `grid_sample`。
网络参数量和普通整图推理路径不增加；训练增加额外前向，完整训练耗时未测定。

## 一次实验的冻结门槛

候选与已有 960 基线均在 960 推理，尺寸分组固定参考 640。
全部 548 张验证图进行正常评估，另在固定 64 张图上做机制诊断。
所有门槛同时通过才输出 `CONTINUE`：

| 指标 | 最低要求 |
|---|---:|
| tiny AP50–95 增量 | +0.50 个百分点 |
| small_all AP50–95 增量 | +0.30 个百分点 |
| all AP50–95 增量 | 不低于 -0.10 个百分点 |
| FPPI <= 10 的 small_all Recall 增量 | +0.50 个百分点 |
| 上述 Recall 增量的配对图像 bootstrap 95% CI 下界 | > 0 |
| tiny 平均对齐特征距离相对降低 | >= 10% |
| tiny 检出翻转率降低 | >= 0.50 个百分点 |

前五项沿用此前的项目投资门槛，后两项检验机制是否朝预期方向改变。
这些门槛是研究投入标准，不是普适显著性标准。Recall bootstrap 固定选定阈值，
不包含训练 seed 的不确定性，也不是 AP 差异的统计显著性证明。

任意有效门槛未过，输出 `STOP`，停止投入这版实例相位一致性方案，
继续保留已验证的 960 基线。若 AP 通过而机制失败，报告中会保留
`utility_passed=true / mechanism_passed=false`，不能据此讲相位稳定性的因果故事。
训练未完成、参数改变、数据或源码不匹配等返回错误，不算方法失败。
不要在看到结果后移动门槛或追加模块“救结果”。

指标为沿用简化 IoF-ignore 的 COCO-style 诊断，**不是官方 VisDrone AP**。
通过之后，正式研究仍需官方评估协议和独立验证。

## 执行

在 PowerShell 中：

```powershell
cd D:\Python\YOLO
conda activate yolo
python scripts/training/train.py --config configs/experiments/phase_960_100.yaml
```

只新增该候选的 100 轮训练。已有 960 基线无需再训练。
脚本禁止更改冻结训练配方、启用 SDCL、续训或静默覆盖已有候选目录。
已有同名目录会报错，避免把先前产物错当作这次训练。

训练完整结束后：

```powershell
python scripts/evaluation/diagnose_phase.py --device 0 --batch 8
```

脚本检查连续 100 轮、完整机制日志、训练配方、数据/包版本/源码、
基线权重 SHA256 和候选检查点中的机制配置。
评估重新抓取两模型的预测，避免使用修改适配器后的过期缓存。
输出到新的 `output/analysis/phase-<时间戳>/`，包含
`plan.json`、`normal/report.json`、两个 `*_phase.json`、
`decision.json` 和 `decision.md`。
`decision` 使用新方法筛选规则，`STOP` 不否定 960 分辨率路线。

若不使用 conda activate，可用当前已验证解释器：

```powershell
& 'C:\Users\BaiRong-NUC\.conda\envs\yolo\python.exe' scripts/training/train.py --config configs/experiments/phase_960_100.yaml
& 'C:\Users\BaiRong-NUC\.conda\envs\yolo\python.exe' scripts/evaluation/diagnose_phase.py --device 0 --batch 8
```

# 分类与回归加权消融

日期：2026-10-06。

## 目的

现有 30 轮 SDCL 的小目标 AP50–95 从 18.929% 到 18.996%。固定置信度 0.25 下
Recall 增加约 0.843 个百分点，同时全图误检增加 793 个；近似相同误检数下，
小目标 Recall 增加约 0.151 个百分点，配对图像 bootstrap 区间包含零。
详见 [按尺寸评估与漏检分析](按尺寸评估与漏检分析.md)。

下一步分别测试分类与回归加权，判断哪些分支改善定位、排序或工作点表现。
分类加权改变置信度分布是待检验解释，尚未确认为误检增加的原因。

## 实现与对照条件

`sdcl.apply_to` 控制加权分支，`signal` 和 `difficulty_alpha` 仍控制权重信号。

| 配置 | apply_to | 正分类监督 | 框回归与 DFL |
|---|---|---|---|
| baseline.yaml | both，enabled=false | 原始损失 | 原始损失 |
| sdcl.yaml | both，省略时的默认值 | 加权 | 加权 |
| sdcl_cls.yaml | classification | 加权 | 原始损失 |
| sdcl_reg.yaml | regression | 原始损失 | 加权 |

仅改变权重作用分支。原始标签分配、软目标、背景分类处理、忽略协议与损失分母保持一致；
回归分支包含框损失与 DFL。两组均保留 `signal: joint`、`difficulty_alpha: 0.5`、
`lambda_max: 0.5`、3 轮权重预热与 10 轮渐进启用。
旧配置及旧检查点缺少 `apply_to` 时解释为 `both`；恢复训练仍拒绝改变分支。

两组新配置默认 YOLO11s、原始 `yolo11s.pt` 预训练权重、30 epoch、batch 8、
640 输入、seed 0、SGD、相同增强与 Windows workers 0。
本次检查逐项对比了历史 `sdcl_yolo11s_seed0/args.yaml`：
除 run 名称和输出位置外，训练参数一致。

## 训练指令

```powershell
conda activate yolo
Set-Location 'D:\Python\YOLO'
```

第一组，仅分类加权：

```powershell
python scripts/train.py --config configs/experiments/sdcl_cls.yaml --epochs 30 --batch 8
```

第一组成功完成后执行第二组，仅框回归与 DFL 加权：

```powershell
python scripts/train.py --config configs/experiments/sdcl_reg.yaml --epochs 30 --batch 8
```

按首次运行的目录名称：

```text
output/runs/sdcl_cls_yolo11s_seed0/
output/runs/sdcl_reg_yolo11s_seed0/
```

两组分别保存 `weights/best.pt`、`weights/last.pt`、`results.csv`、
`experiment.json` 与 `sdcl_statistics.jsonl`。
本次准备时这两个目录均不存在。上游默认 `exist_ok: false`；
同名目录存在时会递增名称，重新运行后应使用控制台实际保存位置进行评估。
已完成的 baseline 与联合 SDCL 无需重跑。
不要以它们被剥离优化器的完成检查点恢复新消融实验。

## 训练后评估

两组都与原来的 30 轮基线比较。以下尺寸评估使用原分析的 640 输入、验证 batch 16、
置信度 0.25；训练 batch 仍为 8。输出目录不得已存在。

```powershell
python scripts/analyze_sizes.py `
  --baseline output/runs/baseline_yolo11s_seed0-2/weights/best.pt `
  --sdcl output/runs/sdcl_cls_yolo11s_seed0/weights/best.pt `
  --output output/analysis/size_30epoch_cls_20261006
```

```powershell
python scripts/analyze_sizes.py `
  --baseline output/runs/baseline_yolo11s_seed0-2/weights/best.pt `
  --sdcl output/runs/sdcl_reg_yolo11s_seed0/weights/best.pt `
  --output output/analysis/size_30epoch_reg_20261006
```

`--sdcl` 是评估器的候选模型参数名；这里可以传分类或回归消融权重。
生成的报告、CSV 和图中 `sdcl` 标签指本次传入的候选模型，不一定是联合 SDCL。
`report.json` 的 `captures` 记录真实检查点路径及哈希，解读时以它们为准。

重点对比：

1. `coco_reference` 中 `small_all`（640 参考尺寸下 <32）的 AP50–95 与 AP50。
2. `matched_fp_budgets` 中小目标 Recall 增量，特别是基线置信度 0.25 对应误检预算。
3. 全图误检、tiny／medium 表现，以及新增检出与丢失的目标。
4. 配对图像 bootstrap 区间仅反映这两个检查点的验证集抽样波动，不代替训练种子复验。

这些仍是尺寸诊断指标，不是官方 VisDrone AP。不要将固定置信度 Recall 上升单独视为
方法有效。分支有一致收益后，再做相同预算的长训和多种子验证；没有清晰收益时，
优先修正加权机制并逐项验证假设。

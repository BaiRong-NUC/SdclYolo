# 代码框架与开始步骤

更新日期：2026-10-04。

## 1. 当前工程状态

项目已从方案文档推进到可运行的首版代码，不是只有目录和空函数。

核心逻辑位于：

| 模块 | 职责 |
|---|---|
| `sdcl/config.py` | 配置校验、相对路径、权重调度 |
| `sdcl/weights.py` | 对象聚合、尺度难度信号、有界与质量守恒 |
| `sdcl/criterion.py` | 保留原分配与软目标，接入分类／回归加权 |
| `sdcl/dataset.py` | 保留忽略区域并与增强同步 |
| `sdcl/geometry.py` | 忽略区域位置掩码、诊断用 IoF |
| `sdcl/trainer.py` | 本地模型／训练器扩展、epoch、日志与清单 |
| `sdcl/data.py` | VisDrone 转换、验收、合成烟测样本 |
| `sdcl/export.py` | VisDrone 八字段格式导出 |
| `sdcl/cli.py` | train、prepare、audit、validate、export、smoke |

基线与 SDCL 使用相同数据与忽略处理，默认配方只有 run 名称与加权开关不同。

不修改已安装 Ultralytics 源码；通过本地 subclass 和 criterion 接口接入。Ultralytics 升级时，必须重新核查接口，当前代码固定适配 8.4.172。

## 2. 你现在先做什么

```powershell

Set-Location 'D:\Python\YOLO'
python -m pip install -e . --no-deps
python -m sdcl env
python -m pytest
```

本次已经在你的 yolo 环境安装了本项目的 editable 包，未升级原有第三方依赖。之后改 `sdcl` 会直接反映到执行结果。

```powershell
python scripts/train.py --config configs/experiments/baseline.yaml --epochs 5 --batch 8
```

目标是确认数据读取、有效标签数量、损失变化、检查点保存和显存，不根据这个短程实验宣布方法效果。

### 第五步：完整基线，再比较核心方法

确认训练配方后，为完整实验选择明确的 `name`、种子和输出目录。保持基线与 SDCL 的其他参数一致。

```powershell
python scripts/train.py --config configs/experiments/baseline.yaml
python scripts/train.py --config configs/experiments/sdcl.yaml
```

不要先调几十个参数。在 1 个种子确认非异常收益后，再做 3 个种子、单信号和协同对照。

默认 12 GB 显存上的 batch 16 尚未在真实密集数据上验收。本次通过的是 batch 8 的单步检查，
完整训练仍需观察增强和验证时的显存；有 OOM 时所有对照统一调整。租卡时沿用已固定配方，并单独记录硬件。

## 4. 必须知道的实现取舍

### 忽略区域

转换器将无效／非评价区域保留为 metadata。加载后临时赋予哨兵类别，与 Instances 一起进入几何增强，在最终格式化后拆分成 `ignore_bboxes`。

优势是避免单独复制复杂增强逻辑。风险是部分混合增强可能按框类别处理，需要逐步验证；当前有翻转与 Mosaic 测试，还未完成所有混合增强、强透视和真实密集场景验收。

### 损失

分类加权只作用于软标签的正项，不改变软目标，也不放大前景位置上的所有负类别项。回归与 DFL 在逐正样本质量权重处施加同一对象权重，原分母保持不变。

### 验证

训练监控使用 Ultralytics 的 AP 流程与简化 IoF 忽略过滤。这不是官方 VisDrone 评价，仍可能与官方有效目标／忽略区域匹配处理不同。

最终评价必须导出预测并使用官方工具核查，尤其是忽略区域、每图最大 500 框、类别和原图坐标。

### 恢复

自定义设置保存在 `experiment.json`，CLI 恢复要求设置和忽略协议一致；epoch 调度从训练器恢复进度同步到模型 criterion。

训练结束后的上游检查点会被剥离优化器，不能当作尚未完成训练的恢复检查点。

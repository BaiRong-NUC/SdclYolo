# 代码框架与开始步骤

更新日期：2026-10-04。

## 1. 当前工程状态

项目已从方案文档推进到可运行的首版代码，不是只有目录和空函数。

核心逻辑位于：

| 模块 | 职责 |
|---|---|
| `src/sdcl/config.py` | 配置校验、相对路径、权重调度 |
| `src/sdcl/weights.py` | 对象聚合、尺度难度信号、有界与质量守恒 |
| `src/sdcl/criterion.py` | 保留原分配与软目标，接入分类／回归加权 |
| `src/sdcl/dataset.py` | 保留忽略区域并与增强同步 |
| `src/sdcl/geometry.py` | 忽略区域位置掩码、诊断用 IoF |
| `src/sdcl/trainer.py` | 本地模型／训练器扩展、epoch、日志与清单 |
| `src/sdcl/data.py` | VisDrone 转换、验收、合成烟测样本 |
| `src/sdcl/export.py` | VisDrone 八字段格式导出 |
| `src/sdcl/cli.py` | train、prepare、audit、validate、export、smoke |

基线与 SDCL 使用相同数据与忽略处理，默认配方只有 run 名称与加权开关不同。

不修改已安装 Ultralytics 源码；通过本地 subclass 和 criterion 接口接入。Ultralytics 升级时，必须重新核查接口，当前代码固定适配 8.4.172。

## 2. 你现在先做什么

### 第一步：进入工程并确认代码可运行

```powershell
conda activate yolo
Set-Location 'D:\Python\YOLO'
python -m pip install -e . --no-deps
python -m sdcl env
python -m pytest
```

本次已经在你的 yolo 环境安装了本项目的 editable 包，未升级原有第三方依赖。之后改 `src/sdcl` 会直接反映到执行结果。

### 第二步：看烟测输出

本次已经运行过：

```text
output/smoke/framework-v1/smoke_report.json
output/smoke/framework-v1/runs/baseline/
output/smoke/framework-v1/runs/sdcl/
output/smoke/framework-v1/export/
output/resume-smoke.log
```

如需自己重跑，使用默认的新目录：

```powershell
python scripts/smoke_test.py --device 0
```

不要对已有 `framework-v1` 输出目录重复执行转换覆盖操作。烟测只用合成样本，AP 无研究意义。

### 第三步：获取真实 VisDrone 数据

按 `data/README.md` 的结构下载、解压 train、val。先核对数据使用条件与实际文件完整性，不用等第二数据集才开始基线。

```powershell
python scripts/prepare_visdrone.py --raw-root data/raw --output data/visdrone
python scripts/audit_dataset.py --dataset data/visdrone
```

请检查 metadata 中的忽略框、遮挡字段，抽样画框确认。真实数据的抽样可视化工具尚未作为独立命令实现，不把自动检查当作视觉验收。

### 第四步：先跑 5 epoch 原始损失基线

```powershell
python scripts/train.py --config configs/experiments/baseline.yaml --epochs 5 --batch 8
```

目标是确认数据读取、有效标签数量、损失变化、检查点保存和显存，不根据这个短程实验宣布方法效果。

### 第五步：完整基线，再比较核心方法

确认训练配方后，为完整实验选择明确的 `name`、种子和输出目录。保持基线与 SDCL 的其他参数一致。

```powershell
python scripts/train.py --config configs/experiments/baseline.yaml
python scripts/train.py --config configs/experiments/sdcl.yaml
```

不要先调几十个参数。在 1 个种子确认非异常收益后，再做 3 个种子、单信号和协同对照。

默认 12 GB 显存上的 batch 16 尚未在真实密集数据上验收；有 OOM 时所有对照统一调整。租卡时沿用已固定配方，并单独记录硬件。

## 3. 已完成的验证

### 3.1 本机环境

- Windows、Python 3.12.4。
- PyTorch 2.10.0+cu128、TorchVision 0.25.0+cu128。
- Ultralytics 8.4.172。
- RTX 4070 Ti，约 12 GB。
- `pip check` 通过。

### 3.2 单元与张量测试

本次最终执行 `python -m pytest`：**21 项通过，0 项失败**。Python 编译检查和新文件空白／Markdown 结构检查也通过。

包含：

- 四种信号的权重边界、质量守恒、同对象共享权重。
- 对象索引跨 batch 不冲突、空前景、零强度和调度。
- 分类 BCE 的零强度前向与梯度一致。
- 完整检测损失在空标签和有效标签条件下与上游一致。
- 转换类别、裁剪、忽略标签、图像与 metadata。
- 忽略区域与翻转／Mosaic 同步，哨兵类别不进入真值。
- CUDA FP16 autocast 前向与反向、有界权重和守恒。
- 基线／方法训练配方一致，多设备请求拒绝。

CUDA 测试使用 GradScaler 初始 scale 128。随机初始化的小型样本在默认 scale 65536 时，原始 YOLO 和 SDCL 都会出现部分梯度溢出；训练器使用动态缩放，测试不把默认首次溢出误认为方法独有问题。真实数据 AMP 训练仍需单独验证。

## 4. 必须知道的实现取舍

### 忽略区域

转换器将无效／非评价区域保留为 metadata。加载后临时赋予哨兵类别，与 Instances 一起进入几何增强，在最终格式化后拆分成 `ignore_bboxes`。

优势是避免单独复制复杂增强逻辑。风险是部分混合增强可能按框类别处理，需要逐步验证；当前有翻转与 Mosaic 测试，还未完成所有混合增强、强透视和真实密集场景验收。

### 损失

分类加权只作用于软标签的正项，不改变软目标，也不放大前景位置上的所有负类别项。回归与 DFL 在逐正样本质量权重处施加同一对象权重，原分母保持不变。

### 验证

训练监控使用 Ultralytics 的 AP 流程与简化 IoF 忽略过滤。这不是官方 VisDrone 评价，仍可能与官方有效目标／忽略区域匹配处理不同。

最终评价必须导出预测并使用官方工具核查，尤其是忽略区域、每图最大 500 框、类别和原图坐标。

### 恢复

自定义设置保存在 `experiment.json`，CLI 恢复要求设置和忽略协议一致；epoch 调度从训练器恢复进度同步到模型 criterion。

训练结束后的上游检查点会被剥离优化器，不能当作尚未完成训练的恢复检查点。

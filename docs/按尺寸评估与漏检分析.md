# 按尺寸评估与漏检分析

此入口比较已训练的两个检查点，不重新训练模型，也不覆盖训练目录。
结果是带现有简化 IoF 忽略过滤的 **COCO 风格诊断评价**，不是官方 VisDrone 指标。

## 运行

```powershell
conda activate yolo
cd D:\Python\YOLO
python scripts/analyze_sizes.py --output output/analysis/size_comparison_new
```

默认检查点：

- baseline：`output/runs/baseline_yolo11s_seed0-2/weights/best.pt`
- SDCL：`output/runs/sdcl_yolo11s_seed0/weights/best.pt`

可用 `--baseline`、`--sdcl` 指定其他检查点。默认输入 640、验证 batch 16、GPU 0，
只处理完整 val。输出目录已存在时拒绝运行。`--confidence` 默认为 0.25，只控制
固定阈值召回与漏检分析，不改变 AP 所使用的最低检测置信度 0.001。

## 尺寸定义

主报告使用真实原图框经等比缩放到参考长边 640 后的面积：

`reference_area = original_box_area * (640 / max(original_width, original_height)) ** 2`

尺寸用面积平方根表示，避免把长宽都小于阈值与面积阈值混淆。

| 分组 | 等效边长 |
|---|---|
| tiny | 小于 16 像素 |
| small | 大于等于 16、小于 32 像素 |
| small_all | 小于 32 像素，tiny 与 small 的并集 |
| medium | 大于等于 32、小于 96 像素 |
| large | 大于等于 96 像素 |

tiny、small、medium、large 是互斥划分；small_all 是补充合并组，不能再次加到总数。
同时保存原图面积口径的结果。两种口径必须分开引用，不能选择其中更有利的结果作为
同一种评价。这里的 tiny 阈值是预先指定的诊断阈值，不是 AI-TOD 官方分组。

## AP 与召回的不同口径

预测来自现有验证器的相同预处理、类别相关 NMS 和忽略过滤路径。忽略框的 IoF
大于 0.5 时过滤预测；每图最多保留 500 个检测框。忽略区域不是新方法的收益。

AP 使用 `pycocotools.COCOeval`：

- 类别宏平均，IoU 从 0.50 到 0.95，步长 0.05，101 个召回采样点。
- AP50 单独列出，同时报告 AR50–95@500。
- 全部有效真值框都进入匹配。评价某面积组时，其他面积组的真值及其匹配由
  COCO 面积规则忽略，避免把其他尺寸的正确检测当成假阳性。
- 面积边界采用左闭右开；无真值类别不参与该组宏平均，无真值组用 null 表示。
- COCO 风格 AP 的匹配和插值方式与 Ultralytics 不同，不要求总体 AP 数值完全相等。

Recall 和漏检采用固定置信度 0.25、IoU 0.50、类别一致的一对一匹配：

- 在全部尺寸真值间，按检测置信度从高到低贪心匹配；再按真值尺寸统计。
- 报告微平均 `TP / GT`，不同于 Ultralytics 默认在选定 F1 工作点的类别宏平均 Recall。
- 补充置信度 0.10、0.50 的召回敏感性，避免只依据一个工作点下结论。
- 用 2,000 次按验证图像配对 bootstrap、种子 0，估计 Recall 差值的 95% 区间。
  此区间不涵盖训练随机种子的不确定性，也不是 AP 的显著性检验。

## 漏检与抵消分析

每个真值以原始 object_id 配对，记录：

- both_detected：两组都检出。
- recovered：基线漏检，SDCL 检出。
- lost：基线检出，SDCL 漏检。
- both_missed：两组都漏检。

互斥尺寸组的 `recovered - lost` 可以直接相加，检验固定工作点下的目标数量抵消。
各尺寸 AP 不能直接相加，也不能据其差值算术平均来解释总体 AP。

另外比较相同全图误检预算下的 Recall，默认预算为每图 5、10、15、20 个 FP，
以及基线在置信度 0.25 下的 FP 数量。两组分别选择不超过预算的最低可行阈值，
保留完整置信度并列组，不能任意拆分同分预测。实际 FP 数也同时列出，因此受并列
分数影响时并不保证实际数量完全相等。此分析检验置信度工作点的取舍，不用于重新
选择训练超参数。其 bootstrap 固定所选阈值，不覆盖阈值选择及训练种子不确定性。

对漏检给出互斥的启发式标签：匹配竞争、低于置信度阈值、类别混淆、定位偏差、
缺少邻近检测。定位偏差要求同类高置信度预测的 IoU 至少为 0.10。
这些标签基于阈值以上或已保留的低置信度预测，不是模型失败原因的因果证明。

## 输出

- `report.json`：两种尺寸口径的 AP/AR、固定召回、置信度敏感性、配对区间和协议。
- `size_comparison.csv`：640 参考口径的核心比较。
- `objects.csv`：所有真值的尺寸、配对状态、漏检标签、遮挡和截断信息。
- `per_image.csv`：每图 TP、GT、FP，支持检查配对重采样和抵消。
- `predictions/`：可追溯的原图坐标预测、检查点与数据设置记录。
- `size_comparison.png`：AP、Recall 和 recovered/lost 对照图。
- `recall_vs_fppi.png` 与两组 `*_recall_fp_curve.csv`：相同误检预算的召回比较。
- `examples/paired_small_objects.png`：新增检出、丢失和持续漏检的成对局部图。

示例按等效边长接近 20 像素、图像名和 object_id 排序，每种状态取三个不同图像；
局部图经过放大，仅供目视检查，不能代表统计显著性。

COCO 匹配规则参考：
https://github.com/cocodataset/cocoapi/blob/master/PythonAPI/pycocotools/cocoeval.py

## 2026-10-06：30 轮检查点实测

最终报告位于 `output/analysis/size_30epoch_20261006_final/`。使用 seed 0 两组最佳权重，
548 张验证图、38,759 个有效目标，640 输入，置信度 0.25，IoU 0.50。
尺寸面积计算已统一，AP、Recall、阈值敏感性的各组 GT 数量一致。

| 640 参考尺寸组 | GT | 基线 AP50–95 | SDCL AP50–95 | 基线 Recall | SDCL Recall | 净新增 TP |
|---|---:|---:|---:|---:|---:|---:|
| tiny，<16 | 27,084 | 12.586% | 12.742% | 38.008% | 38.949% | +255 |
| small，16–32 | 8,743 | 32.693% | 32.829% | 75.363% | 75.901% | +47 |
| small_all，<32 | 35,827 | 18.929% | 18.996% | 47.124% | 47.967% | +302 |
| medium，32–96 | 2,897 | 45.449% | 46.937% | 88.402% | 88.367% | −1 |
| large，≥96 | 35 | 43.673% | 51.298% | 71.429% | 77.143% | +2 |

large 只有 35 个目标，不能据较大的点估计宣称稳定收益。small_all 是前两行的并集，
不能重复计入总数。AP 不可按该表各组直接相加。

small_all 中新增检出 1,197 个，同时丢失 895 个，净增加 302 个；
medium 净减少 1 个，large 净增加 2 个。全体净增加 303 个。
固定置信度下的主要收益没有被中大目标损失抵消。

但全图误检从 10,139 增加到 10,932，增加 793 个。控制到基线误检预算后，
两组实际误检分别为 10,139 和 10,132，小目标 Recall 从 47.124% 到 47.274%，
只提高约 0.151 个百分点。配对图像 bootstrap 的 95% 区间约为
`[-0.098, +0.399]` 个百分点，包含零。对应阈值约为 0.25024 与 0.26123，
它们是诊断工作点，不是重新选择的训练参数。

固定置信度 0.25 的小目标 Recall 差值为 +0.843 个百分点，配对图像区间约为
`[+0.594, +1.097]`。两种区间都只针对这两个已训练检查点和验证图像抽样，
不能代替多训练种子的复验。

当前证据支持“小目标固定工作点召回略有改善，但主要伴随更多误检”。
相同误检预算下尚未证明稳定优势。更接近于工作点／置信度分布变化的解释，
仍需分类加权与回归加权分别消融验证，不能视为已证实的因果关系。

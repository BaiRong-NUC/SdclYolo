# 新候选：匹配阈值净收益监督，一次缓存预检

登记：2026-10-13。本登记先于前三个坐标候选的 test-dev 官方结果。
来源是此前 val 的事后条件过阈值诊断，不使用本轮 test-dev 标签选择超参数。
它是待验证的新假设，不是已经确定的原创损失。

## 固定实验

复用 6471 张 train 的动作特征、有效掩码、原 GT 归属 IoU 标签、逆采样权重及场景划分。
复用冻结 mean/std，不新增检测器训练或训练图像推理。
动作集合、原框身份、输入 68 维、保持原框的分数/类别/数量/顺序规则不变。

两头容量、初始化、批次顺序、优化器和轮数完全相同：
68 -> 64 -> 64 -> 10，每个输出对应固定官方 IoU 阈值 0.50:0.05:0.95。

- threshold_absolute：回归各动作在每个阈值是否匹配原 GT 的 0/1 标签。
- threshold_gain：回归动作相对 keep 在每个阈值的标签差，范围 -1/0/+1。

两头都使用 SmoothL1 beta0.1，按有效动作和十个阈值平均，并保留原逆采样权重。
选择时对十个预测输出取均值；absolute 用相对其 keep 的差，gain 用相对标签输出。
预测收益 >0.01 才替换。固定 seed0、20 epoch、batch2048、AdamW lr0.002/wd0.0001。
固定最后 epoch20，train 内场景监控只记录，不选最优 epoch。

保持检测分数不变的条件过阈值监督不等于直接优化完整 AP：它不覆盖官方重新匹配、
全部 FP、评分排序和未被原框拥有的 GT。这些限制在结果中必须保留。
阈值来自官方评价定义；用户要求降低的是投入收益门槛，不改变官方匹配阈值。

## 固定确认标准

使用共享的 1610 张 test-dev 动作缓存，GT 只进入评价，不进入预测。

主要比较：threshold_gain 对 threshold_absolute 的官方 AP，要求点估计 >0。
相对普通校准，AP 至少 +0.10 pp、AR500 >=-0.50 pp；
使用与前面候选相同的温和预算标准，不宣称统计显著。

另外事先登记相对冻结 gain、uniform、regret 的比较。
即使超过新匹配头，若 AP 仍未超过已冻结 regret，则标为
“机制信号存在但未超过当前排序方案”，不包装成新的强对照。
AR 与成本的取舍单独列出，不要求十个阈值/所有尺寸同时增加。

官方结果来自已经登记的同一 test-dev；在多个候选上复用它，不是新的未查看测试集。
本方案和参数在前三个候选结果出来前固定，仍须披露验证集选择历史、多重候选筛选、
一套种子及没有官方 AP 区间等限制。

## 创新边界与停止规则

AP-Loss、Rank & Sort、IoU-Net、GFL 等已研究评价对齐、质量预测或定位质量排序。
不把这些一般原则当首创。本次只检验固定原框身份下，多阈值相对监督是否有独立收益。
通过仅允许保留该机制候选、追加更近的全文对照和独立确认；不自动升级为论文贡献。

本轮只训练这两个小头一次，不增加 epoch、改阈值、挑最好 checkpoint 或反复换种子。
无收益时停止此配方，不否定整个小目标领域。

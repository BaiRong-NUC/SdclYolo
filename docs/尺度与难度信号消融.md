# 尺度与难度信号消融

日期：2026-10-09。

## 目的与已有结果

原版联合 SDCL 已完成 seed 0、1、2 的 100 轮对照及统一尺寸评估。
整体 Ultralytics 诊断 mAP50–95 的平均差值为 -0.026 个百分点；
COCO 风格 small_all AP50–95 平均 +0.098，tiny AP50–95 平均 +0.146 个百分点。
tiny AP 与 FPPI 5 下小目标 Recall 在三个种子中方向一致，但中目标平均 AP 下降。
这些是局部收益的初步证据，不是全面提升、显著性结论或官方 VisDrone 指标。

本次只拆分权重信号，先在 seed 0 下筛查机制。若某种信号有希望，再补 seed 1、2，
避免根据一组结果调整后就宣称稳定有效。已有基线与联合实验无需重新训练。

## 对照条件

| 方法 | 配置 | 信号 | 状态 |
|---|---|---|---|
| 基线 | baseline_100.yaml | 不启用权重 | 已完成 |
| 联合 | sdcl_100.yaml | scale × difficulty | 已完成 |
| 仅尺度 | sdcl_scale_100.yaml | scale | 本次新增 |
| 仅难度 | sdcl_difficulty_100.yaml | difficulty | 本次新增 |

两份新增配置与 `sdcl_100.yaml` 只在 run 名和 `sdcl.signal` 上不同。
均为原始 `yolo11s.pt` 初始化、100 epoch、batch 8、640 输入、seed 0、SGD、
workers 0，相同增强与忽略协议。保留 `apply_to: both`、
`classification_weighting: positive_term`、`lambda_max: 0.5`、3 轮预热和 10 轮渐进调度。
网络、标签分配、损失分母以及背景监督处理保持一致。

现有 `object_weights` 已支持这三种信号，无需更换损失公式。
尺度分支不受预测概率／IoU 难度输入影响；难度分支在其余输入固定时不受框尺度影响。
这与分类／回归加权分支消融不同：本次两个损失分支都启用，只改变权重的构成信号。

虽然两组 `lambda_max` 相同，三个信号的分布与最终权重波动幅度可能不同。
因此不能把差异解释成等实际权重强度下的纯因果贡献；同时检查已有
`sdcl_statistics.jsonl` 中的权重范围、强度和质量守恒误差。

## 执行训练

一次启动，成功完成仅尺度组后自动运行仅难度组：

```powershell
conda activate yolo
Set-Location 'D:\Python\YOLO'
python scripts/train_signal_ablation.py
```

这个入口只运行两组新增实验，直接使用终端显示进度，不生成额外控制台日志或备份。
任何非零退出或 Ctrl+C 会停止后续实验。保留正常模型权重、指标和实验清单。
已有目标目录时停止并保留文件，避免自动产生重复的实验目录。

可先检查而不训练、不写文件：

```powershell
python scripts/train_signal_ablation.py --dry-run
```

也可逐条执行以下单组命令；与队列二选一，不要同时执行：

```powershell
python scripts/train.py --config configs/experiments/sdcl_scale_100.yaml
python scripts/train.py --config configs/experiments/sdcl_difficulty_100.yaml
```

首次输出为：

```text
output/runs/sdcl_scale_yolo11s_100ep_seed0/
output/runs/sdcl_difficulty_yolo11s_100ep_seed0/
```

如果第一组已经成功、第二组中断，只处理第二组，不再次启动整套队列。
若该组有未完成且保留优化器状态的 `last.pt`，可单独恢复，例如：

```powershell
python scripts/train.py --config configs/experiments/sdcl_difficulty_100.yaml --resume output/runs/sdcl_difficulty_yolo11s_100ep_seed0/weights/last.pt
```

不使用已完成且被剥离优化器的检查点恢复训练。单组同名重跑会递增目录名，
评估时以控制台实际保存路径为准。

## 训练完成后评估

两组分别与同一 seed 0 基线比较，使用已有评估协议：

```powershell
python scripts/analyze_sizes.py `
  --baseline output/runs/baseline_yolo11s_100ep_seed0/weights/best.pt `
  --sdcl output/runs/sdcl_scale_yolo11s_100ep_seed0/weights/best.pt `
  --imgsz 640 --batch 16 --confidence 0.25 --device 0 `
  --output output/analysis/size_100epoch_scale_seed0_20261009
```

```powershell
python scripts/analyze_sizes.py `
  --baseline output/runs/baseline_yolo11s_100ep_seed0/weights/best.pt `
  --sdcl output/runs/sdcl_difficulty_yolo11s_100ep_seed0/weights/best.pt `
  --imgsz 640 --batch 16 --confidence 0.25 --device 0 `
  --output output/analysis/size_100epoch_difficulty_seed0_20261009
```

`--sdcl` 是候选模型参数，这里可传不同信号的检查点。
输出目录不得存在；再次评估用新的输出目录。
比较这两份报告与已有 `output/analysis/size_100epoch_seed0_20261008/report.json`。
AP 在同一指标体系内比较，不混用原生 Ultralytics、尺寸诊断和官方 VisDrone AP。

重点看 tiny／small_all AP50–95、FPPI 5／10 下 Recall，以及 medium AP 是否恢复。
只有固定阈值 Recall 增加而 FP 同时增加，不视为充分收益。
若仅尺度更好，检查难度信号或联合形式；若仅难度更好，检查尺度偏置；
若都没有改善，再重新设计核心机制。这些是待检验解释，不预先认定原因。

seed 0 联合 SDCL 曾在 61 轮后恢复，因此本轮只是已有 seed 0 对照上的探索性消融；
不能声称恢复运行与连续运行逐位等价。候选方案确定后仍需跨种子复验。
准备配置和通过测试不等于两组已训练，本次由用户执行训练。

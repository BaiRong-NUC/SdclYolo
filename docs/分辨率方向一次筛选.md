# 分辨率方向一次筛选

日期：2026-10-10。状态：准备一组新训练，评估后按固定门槛决定是否继续投入。

## 目的与预算

暂停继续调整 SDCL 权重。只新增一组 YOLO11s、960 输入、100 epoch、
batch 8、seed 0 的基线训练，SDCL 关闭，保留现有忽略区域处理。
从原始 `yolo11s.pt` 初始化；不从已完成的 640／SDCL 检查点微调。
训练配方除输入分辨率和运行名称外与 `baseline_100.yaml` 相同。
100 epoch／相同 batch 表示相同训练轮数预算，不表示相同计算量或耗时。

已有 640 基线为 `output/runs/baseline_yolo11s_100ep_seed0/weights/best.pt`，
无需重跑。两组均使用 best.pt，与原有最佳检查点评价规则一致。
检查点选择和此次方法筛选均使用验证集，后续正式结论仍需独立测试。

本实验检验整图高分辨率训练是否有足够的增量价值，不能一次排除所有
小目标检测、标签分配或细节保留方法，也不是一个新方法的创新证明。

## 先训练这一组

```powershell
conda activate yolo
Set-Location 'D:\Python\YOLO'
python scripts/train.py --config configs/experiments/baseline_960_100.yaml
```

首次输出：

```text
output/runs/baseline_yolo11s_960_100ep_seed0/
```

重复训练会由上游递增目录名。评估时用 `--candidate` 指定实际 best.pt，
不要误评旧目录。中断后仅在 last.pt 保留优化器且训练尚未完成时恢复：

```powershell
python scripts/train.py --config configs/experiments/baseline_960_100.yaml --resume output/runs/baseline_yolo11s_960_100ep_seed0/weights/last.pt
```

方向筛选入口要求连续训练配方，当前不接受 `resume: true` 的训练清单。
如果实际发生恢复，先核对保存参数和恢复记录再解释结果，不据恢复运行
自动宣布本次预定连续训练对照成立。

不要为了运行方便单独改变这组 batch、seed、优化器、增强或 epoch；
改变后已不满足本次预定对照。既有其他实验无需继续训练。

## 完成后执行一次方向判定

```powershell
python scripts/diagnose_resolution.py --device 0 --batch 8
```

默认创建唯一时间戳目录：

```text
output/analysis/resolution-<timestamp>/
  plan.json
  inference_only/report.json
  training_increment/report.json
  decision.json
  decision.md
```

入口先检查两组训练清单、数据哈希、epoch 完成记录和批次配方。
无效对照报错，不会把配方不一致当成方向失败。输出目录存在时拒绝覆盖。
新目录可以用 `--output` 指定。

评估只需捕获三组预测：

| 检查点 | 推理输入 | 用途 |
|---|---:|---|
| 已有 640 训练基线 | 640 | 现有部署工作点 |
| 已有 640 训练基线 | 960 | 单纯推理放大的收益 |
| 新 960 训练基线 | 960 | 同推理计算配置下的训练增量 |

第二份报告复用第一份报告的 640 训练／960 推理预测，复用前检查检查点、
数据、适配器、推理配置和预测文件哈希。尺寸分组始终固定在参考长边 640：
tiny <16，small 16–32，small_all <32，medium 32–96。
AP 使用低阈值完整预测，Recall 比较相同全图 FPPI 预算。
报告仍是带现有简化 IoF 过滤的 COCO 风格诊断评价，不是官方 VisDrone AP。

## 事先固定的停止标准

主判定比较 **960 训练／960 推理减去 640 训练／960 推理**。
不能用“新模型 960 推理减去旧模型 640 推理”替代，以免将增加推理计算
获得的收益全部算成训练收益。

本项目把下列数值作为最低值得继续投入的门槛，单位均为百分点。
这些是投入决策标准，不是通用学术标准，也不是 AP 显著性阈值。
它们在看到本次新训练结果之前固定，不随结果降低门槛。

| 主判定指标 | 门槛 |
|---|---:|
| tiny AP50–95 差值 | >= +0.50 |
| small_all AP50–95 差值 | >= +0.30 |
| 整体 AP50–95 差值 | >= -0.10 |
| FPPI 10 下 small_all Recall 差值 | >= +0.50 |
| 上一行 Recall 差值的图像配对 bootstrap 95% 区间下界 | > 0 |

五项全部通过：`CONTINUE`，继续研究有限计算预算下的小目标细节保留机制。
它仅说明该切入点值得下一阶段投入，高分辨率基线本身不能作为论文新贡献。

任一项未通过：`STOP`，结束当前整图高分辨率训练路线，不再对这一配方
追加 seed、轮数或参数搜索。保留数据和工程，另选核心机制。
如果仅推理放大有收益，报告会单独列出；不把它当成高分辨率训练通过。

即使通过，单个训练 seed 仍不证明稳定性。bootstrap 区间只涵盖验证图像
抽样且固定已选择的置信度阈值，不包含训练随机性、阈值选择不确定性，
也不是 AP 显著性检验。一次筛选提供明确的投入决策，而非绝对因果结论。

## 单独评估接口

只有需要另行检查时才执行；不必在方向入口之后重复运行。

```powershell
python scripts/analyze_sizes.py --baseline output/runs/baseline_yolo11s_100ep_seed0/weights/best.pt --candidate output/runs/baseline_yolo11s_960_100ep_seed0/weights/best.pt --baseline-imgsz 960 --candidate-imgsz 960 --reference-size 640 --batch 8 --device 0 --output output/analysis/resolution_manual_new
```

`--candidate` 沿用旧报告的内部 `sdcl` 槽位，仅是检查点参数名，
并不表示训练使用 SDCL。

## 本机预检查

2026-10-10，在 RTX 4070 Ti 上，960／batch 8 已完成一个真实训练数据增强
密集批次的 AMP 前向、反向及 SGD 更新。该批有 5,784 个有效 GT；
损失和梯度有限，CUDA 峰值已分配显存约 7,428 MiB，预留约 8,014 MiB。
详细记录位于 `output/verification/resolution_20261010/memory_960_batch8.json`。
这只验证一次真实批次链路，不保证所有增强组合、训练验证阶段都不会 OOM，
也不代表完整训练或方向有效。

相关配置、尺寸评价和判定回归测试共 56 项通过。真实 640 基线 best.pt
已在两张合成验证图上完成 640／960 捕获和跨角色缓存复用，复用结果一致。
测试验证了接口与复用链路，不使用合成图指标判断方向，也未启动完整新训练。
